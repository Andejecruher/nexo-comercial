# Internal agenda simplification
Collapse the over-built internal-agenda module into the existing "Jornada y Eventos" flow: one module, one view, a `public`/`private` event classification, and hardened public/AI exposure.
Branch: `feat/internal-agenda-simplification`. Delivery: `feature-branch-chain` (user-selected 2026-11-08); test runners: backend Jest (+ `test:postgres` against local PostgreSQL) and frontend Vitest.

## Specs
S1. “Eliminar el nuevo ítem/sub-ítem de la ‘Agenda Interna’” in the admin sidebar; only the existing “Jornada y Eventos” entry remains. “Eliminar el módulo de permisos `agenda_interna`” from `permissions.seed.ts` and `role-permissions.seed.ts`; event control stays under existing `eventos.*`. “Eliminar o depreciar el router `/api/v1/admin/jornada/internal-agenda`”; all event CRUD (public + private) centralizes in existing `/api/v1/admin/events` endpoints.
S2. “Mantener la columna `visibility` en la tabla `events`” with `enum EventVisibility { public private }` (“Cambiar 'internal' por 'private' para alinearse con el lenguaje del equipo”). User decision (2026-11-08): drop `event_internal_details` (trigger, function, table, Prisma model, and the `InternalAgendaOwner` relation on `User`) via a new migration; keep the `idx_events_visibility_*` indexes.
S3. Public exposure is the ONLY restriction for private events: `GET /api/v1/public/eventos/semana` returns only `visibility = 'public'` events; `POST /api/v1/public/eventos/:eventId/asistencia` returns 404 for private events; AI/WhatsApp tools (`getWeeklyEvents`, `getMunicipalInfo`) never query or return them (repository public methods keep rigid `visibility: 'public'` + `status: 'published'`). In the admin event management section, private events work exactly like public ones: citizen registration (RSVP), check-in, and mass invitations/outbox enqueue operate normally.
S4. Unified admin UI in `frontend/components/admin/events-view.tsx`: single list/calendar; clear Público/Privado badge per event; optional quick visibility filter (Todos/Públicos/Privados) in the same screen; `visibility` field in the create/edit form.
S5. Verification: `pnpm --dir backend run typecheck`, `pnpm --dir frontend run typecheck`, and regression suite `backend/src/__tests__/postgres/event-visibility.postgres.test.ts` proving a private `status = 'published'` event is absent from public queries and the AI bot.
